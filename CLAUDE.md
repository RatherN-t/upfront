# CLAUDE.md

Operating instructions for agents working in this repo.

## What this is

**Upfront** — a receivables-financing marketplace built on Pinch Payments.
Businesses sell committed contract revenue or open invoices at a discount;
ordinary retail investors fund the advance; collections route back automatically
on the Pinch rail, which Upfront operates as master merchant.

Hackathon prototype. Test mode only. No real money moves.

## Read before changing anything

| Doc | When |
|---|---|
| `docs/00-decisions.md` | Always. Tells you what is settled and what reverses it |
| `docs/05-honest-returns.md` | Before touching any return, yield or loss figure |

## The rule that matters most

**Every financial figure in this repo comes from exactly one of two places:**

1. `engine/FIGURES.json`, regenerated by `python3 tools/check.py figures`
2. An external source cited inline on a `[source: ...]` line

There is no third category. A number with no origin is a bug. The `figures`
guard fails the build on untraceable figures, and it exists because v1 shipped
hardcoded numbers in prose that had drifted from the engine.

If you change an assumption, regenerate figures and update the prose. Do not
hand-edit a number to match a doc.

## The second rule

**Never state a yield without its downside.** Mean, 5th percentile and
probability of loss travel together. The `claims` guard enforces this within an
eight-line window across all markdown.

This is not decoration. This product's whole credibility problem is that a
mid-teens return looks safe and is not. See `docs/05-honest-returns.md`.

## Verification

```bash
python3 tools/check.py check              # figures + tests + guards
python3 tools/check.py prove              # prove guards catch real regressions
python3 tools/check.py install-git-hooks  # once per checkout
```

A clean pass is not proof. `prove` injects a real regression, confirms the guard
fails for the right reason, restores, and confirms it passes again. Guards that
cannot be proven this way are reported as unproven rather than quietly trusted.

Git does not auto-enable hooks from a fresh clone. Run `install-git-hooks` once.

## Domain vocabulary — use these words exactly

| Term | Means |
|---|---|
| **Face** | Contracted amount before any haircut |
| **Eligible face** | After the screen and the concentration cap |
| **Gross collections** | Eligible face less expected customer bad debt |
| **Net settled** | Gross collections less Pinch fees. **This is what you price against** |
| **Fee drag** | Pinch cost as a share of collections. An underwriting input, not overhead |
| **Continuation** | Share of the remaining stream that survives business failure. 75% invoice, 15% contract |
| **WAL** | Weighted average life. 3.12 months on a flat 26-week book, not 6 |
| **Recourse** | A direct-debit mandate from the business to Upfront. Not a clause |
| **Rail Score** | The grade. Never "Grade A-" — ASIC has views on agency-style ratings |

Using "receivable" for subscription revenue is the mistake that produced v1's
wrong loss model. A subscription is service not yet delivered. Say "contract
revenue" or "future revenue", not "receivable".

## Pinch invariants

- `pinch-version: 2020.1` on every request
- `Current-Merchant: mch_...` on every call made for a financed business, never on
  Upfront's own. A call that omits it silently hits the wrong account
- Amounts are **integer cents**. The `money_type` guard catches float money
- `Nonce` on every money-moving call. Retrying without one double-charges
- Verify `pinch-signature` before parsing a webhook body
- Idempotent on `evt_` id. Events arrive twice
- A payment can settle and then reverse days later. Model a week as a state
  machine, never a boolean
- Soft codes retry: `insufficient-funds`, `temporary-problem`, `technical-error`.
  Hard codes never do: `blocked-by-bank`, `invalid-card`, `invalid-account`,
  `unsupported-card`. Retrying a hard code burns $5 for nothing

Endpoints already documented wrongly once, now guarded:
`POST /merchants/managed` not `/merchants`;
`GET /plans/{id}/calculated-payments` not `POST /plans/calculate`;
Application (not Merchant ID) auth against `auth.getpinch.com.au/connect/token`.

The live connection lives in `integration/`: `pinch_client.py` (token cache,
`as_merchant()` header safety, Time-Travel), `adapter.py` (live JSON -> engine
Book), `seed_sandbox.py` (create a real test book end to end). Route every Pinch
call through the client; never raw HTTP. Amounts are integer cents — the client
rejects floats. Application fees on `POST /payments` are how Upfront earns
in-flight.

## Assumptions under standing suspicion

These broke once. Check whether a change is a new instance before looking for
anything exotic.

1. Fee drag treated as overhead rather than an underwriting input
2. Subscription revenue modelled as a receivable
3. Default probability taken from the economy-wide base rate rather than the
   adversely-selected financed population
4. Expected loss quoted as a mean with no distribution behind it
5. Cash drag ignored
6. Platform unit economics never checked against a real cost base

## Style

Follow the local house style: terse, decision-carrying, no template scaffolding.
Do not add a section that would say nothing. Do not invent owners, dates or
milestones. If scope is unclear after reading, ask one batched question and stop.

Write numbers with their units and their uncertainty. "13.29% p.a., 5th
percentile 2.49%" beats "about 13%".
